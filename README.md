## 🔍 Детальное описание проблем

### BUG-001: Рассинхрон UI и API (Критический)

**Суть проблемы:** При отправке анкеты фронтенд отображает модальное окно «Ваша анкета отправлена» (статус «Успех»), однако сервер возвращает ошибку `422 Unprocessable Entity`. Пользователь ошибочно считает, что заявка ушла, хотя данные не сохраняются.

**Причина:** Логика обработки ответа в JS-коде реагирует на факт отправки запроса (`fetch started`), а не на успешный HTTP-ответ (`response.ok`).

**Шаги воспроизведения:**
1. Открыть форму анкеты.
2. Заполнить все поля (включая дату рождения).
3. Нажать «Отправить».

**Фактический результат:**
- Появляется окно успеха с зелёной галочкой.
- В Network вкладке статус запроса: `422`.
- Данные не попадают в CRM.

**Ожидаемый результат:**
- При ошибке валидации — показать понятное сообщение об ошибке, окно успеха **не отображать**.
- Форма должна оставаться заполненной для исправления.

**Бизнес-влияние:** Потеря кандидатов. Пользователь думает, что откликнулся, но рекрутер заявку не получает.

**Теги:** `bug`, `frontend`, `api`, `critical`, `validation`

### BUG-002: Искажение даты рождения (Критический)

**Суть проблемы:** Дата рождения, введённая пользователем в формате `DD.MM.YYYY` (например, `09.09.2000`), искажается при передаче на бэкенд. В запросе приходит мусорное значение (например, `344-22-43`), из-за чего сервер не может распарсить дату и возвращает `422`.

**Локализация:** Проблема на этапе сериализации данных перед отправкой (JS).

**Теги:** `bug`, `frontend`, `api`, `critical`
